# Cryptoservice

Микросервис на Go для мониторинга, кэширования и агрегации курсов криптовалют в реальном времени с фоновым обновлением данных и интеграцией с CoinGecko API.

## Основной функционал
* **Интеграция с внешним API:** Отказоустойчивый клиент для CoinGecko API, запрашивающий актуальную стоимость токенов.
* **Аналитика и агрегация данных:** API-эндпоинты для расчета метрик (`MIN`, `MAX`, `AVG`) по ценам монет на стороне PostgreSQL.
* **Background Worker:** Фоновый демон-воркер на базе `cron`, который каждую минуту автоматически обновляет курсы валют в БД.
* **Автоматическое управление схемой БД:** Интегрированный мигратор, обновляющий структуру таблиц до запуска приложения.
* **Контейнеризация и DevOps:** Оптимизированный `Dockerfile` с многоэтапной сборкой (**Multi-stage build**) для минимизации размера продакшн-образа. Оркестрация через Docker Compose с контролем инициализации сервисов через `healthcheck`.
* **Документация:** Интерактивная спецификация Swagger / OpenAPI.

## Стек технологий
* **Language:** Go (Golang)
* **Database:** PostgreSQL 16 + golang-migrate
* **DevOps:** Docker, Docker Compose (Multi-stage build)
* **API Specs:** Swagger / OpenAPI
* **Task Automation:** Taskfile

## Переменные окружения (.env)
Для запуска проекта необходимо создать файл `.env` в корневой директории и заполнить его по следующему шаблону:

```env
DB_NAME=cryptodb
DB_USER=postgres
DB_PASSWORD=secret_password
COINGECKO_API_KEY=your_actual_api_key_here
```

## Быстрый старт и запуск

### 1. Клонирование репозитория
```bash
git clone https://github.com/AMKrutikov/cryptoservice
cd cryptoservice
```

### 2. Настройка окружения
Создайте файл `.env` в корневой директории приложения и укажите ваши настройки базы данных и API-ключ CoinGecko.

### 3. Развертывание в Docker
Сборка образов, запуск PostgreSQL, автоматическое накатывание миграций и старт Go-приложения выполняются одной командой:
```bash
docker-compose up --build
```
*Приложение будет доступно по адресу:* `http://localhost:8080`

## 🛠 Автоматизация (Taskfile)
В проекте настроена автоматизация рутинных задач с помощью утилиты `Task`. 

### Установка зависимостей и кодогенерация
* `task install` — установить необходимые инструменты (`mockery`, `migrate`, `swag`).
* `task mock` — запустить генерацию моков через `go generate`.
* `task swagger` — сгенерировать файлы спецификации Swagger.

### Локальная разработка и Docker
* `task run-app` — запустить приложение локально с конфигурационным файлом.
* `task run-app-docker` — собрать и запустить инфраструктуру в фоновом режиме через Docker Compose (`up -d`).
* `task down-app-docker` — остановить и удалить контейнеры окружения (`down`).

### Управление миграциями (внутри Docker)
* `task migrate-docker-create NAME=<название>` — создать файлы новой миграции внутри контейнера.
* `task migrate-docker-up-bystep N=<количество>` — накатить `N` миграций вперед в Docker (по умолчанию N=1).
* `task migrate-docker-down-bystep N=<количество>` — откатить `N` миграций назад в Docker (по умолчанию N=1).

### Управление миграциями (локально)
* `task concreit-migrate-create NAME=<название>` — создать файлы новой миграции локально.
* `task migrate-up` — применить все доступные локальные миграции к БД.
* `task migrate-up-bysteps INT=<шаг>` — применить определенное количество шагов миграций вперед.
* `task migrate-down` — откатить все локальные миграции.
* `task migrate-down-bystep N=<количество>` — откатить определенное количество шагов миграций назад (по умолчанию N=1).
